# check-to-run

記事「レビューを繰り返させるより、チェックを渡す — Claude Code に「正しい」と言わせず、証拠を出させる」で使ったデモです。

バグを 4 つ入れた小さな TypeScript のモジュールを、Claude Code（`claude -p`）に 3 通りのやり方で直させ、結果を比べます。

| 条件 | やり方 | 判定するもの |
|---|---|---|
| A（`run-a.sh`） | チェックを渡さず、終わったら報告させる | Claude の自己申告 |
| B（`run-b.sh`） | 読むだけのレビュアーが承認するまで、レビューと修正を繰り返す（最大 5 往復） | レビュアー |
| C（`run-c.sh`） | 合否が返るチェックを渡し、通るまで続けさせ、証拠を貼らせる | スクリプト |

`run-t.sh` は追加の実験です。仕様だけを見せてテストを書かせ、バグ入りの実装と直した実装の両方に当てます。

## 構成

| パス | 内容 |
|---|---|
| `base/` | 仕様（`SPEC.md`）と、バグ入りの実装（`src/billing.ts`） |
| `checks/` | 条件 C で渡すテストと、それを 2 つのタイムゾーンで実行する `check.sh` |
| `judge/` | 採点用のテスト。どの条件のプロンプトにも含めず、実行後の採点だけに使う |
| `common.sh` | 各スクリプトの共通の設定 |
| `runs/` | 実行すると作られる作業場所。条件ごとのコードとログが入る（Git の管理外）。同じ条件を実行し直すと、前回の分は消える |

## 必要なもの

- Claude Code（2.1.326 で確認）
- Node.js 24（TypeScript をそのまま実行するため）
- jq、bash

## 実行する前に

- **Claude Code が、確認なしでコマンドを実行します。** `--permission-mode auto` で動かすためです。中身を確かめてから、使い捨ての環境（コンテナや VM）で実行することをおすすめします。
- **個人の設定は読み込みません。** 条件をそろえるため、`--setting-sources project,local` と `--strict-mcp-config` を付けています。`~/.claude/settings.json` に書いた許可・拒否のルールも、この実行には効きません。
- **採点用のテストは、読めないようにはしていません。** `judge/` と `base/` は同じチェックアウトの中にあり、読み取りは禁止していません。記事の実験では、どの条件も作業フォルダの外は読んでいませんでした。
- **料金がかかります。** 条件 B は、Claude Code を最大 10 回呼び出します。

## 使い方

```bash
./run-a.sh
./run-b.sh
./run-c.sh
./run-t.sh                     # run-c.sh のあとに実行する

judge/judge.sh base            # バグ入りの実装を採点する（5 つ中 4 つ失敗する）
judge/judge.sh runs/a          # 条件 A の結果を採点する
```

`judge.sh` は、どちらかのタイムゾーンで 1 つでも失敗すると、終了コード 1 を返します。

モデルを変えるときは、`MODEL` と `SUFFIX` を指定します。結果は `runs/a-haiku` などに出ます。

```bash
MODEL=haiku SUFFIX=-haiku ./run-a.sh
```

## 記事での結果

各条件を 1 回ずつ実行しました。モデルの出力は毎回変わるので、同じ結果になるとは限りません。

| 条件 | claude-fable-5-2 | claude-haiku-5-5 |
|---|---|---|
| A | 全部通過、28 行 | 全部通過、31 行 |
| B | 全部通過、レビュー 2 回、28 行 | 全部通過、レビュー 4 回、90 行 |
| C | 全部通過、29 行 | 全部通過、32 行 |

元の実装は 28 行です。
